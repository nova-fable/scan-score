# ScanScore — 乐谱扫描/曲库/播放桌面应用 实施计划

## Context

全新项目（工作区为空）。目标：一款桌面应用，导入 PDF/PNG 乐谱 → OMR 识别成 MusicXML → 存入曲库 → 在应用内查看乐谱并播放。支持钢琴谱、吉他谱（五线谱）；六线谱走 Guitar Pro 文件导入（开源 OMR 无法识别 TAB 谱）。定位个人自用/开源，先出 macOS（Apple Silicon）版本。

## 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | Tauri 2 + React 18 + TypeScript + Vite | 用户指定 Tauri+React |
| UI | Tailwind CSS + shadcn/ui，界面全中文 | 快速出桌面级 UI |
| 状态 | TanStack Query（Rust 数据）+ zustand（播放器状态） | 轻量够用 |
| OMR | **Audiveris 5.4**，独立进程调用（CLI batch 模式，输出 .mxl） | 开源准确率最好；个人/开源项目无 AGPL 顾虑 |
| 乐谱渲染+播放 | **alphaTab**（npm，MIT） | 一库解决 MusicXML/GP 渲染 + 钢琴/吉他谱显示 + WebAudio 内置合成器播放 |
| PDF 光栅化 | Rust `pdfium-render` + 打包 pdfium dylib | 生成页面图/封面 |
| 数据库 | `rusqlite`（SQLite） | 数据层全在 Rust，便于文件管理 |
| 吉他 TAB | Guitar Pro 文件（.gp3~.gp5/.gpx）直接导入，alphaTab 原生渲染播放 | 绕开 OMR 不支持 TAB 的限制 |

## 架构与数据流

```
导入 (PDF/PNG/JPG/MusicXML/GP)
  ├─ MusicXML/GP → 直接 status=ready，可渲染播放
  └─ PDF/PNG → 复制入库 → [识别任务队列]
        → Rust 调 Audiveris CLI: java -jar Audiveris.jar -batch -export -output-dir ... <input>
        → 产出 .mxl → 解析元数据(标题/作曲/声部) → status=ready
  → 曲库 (SQLite + app-data 文件)
  → 详情页: alphaTab 加载 MusicXML/GP → 渲染谱面 + WebAudio 播放
```

- PDF 由 pdfium 光栅化出页面 PNG（封面/预览用）；识别输入 Audiveris 直接收 PDF（PDFBox 支持，spike 验证，不行则喂 PNG）。
- 播放直接由 alphaTab 从 MusicXML/GP 合成音频，不落 MIDI 文件；导出 MIDI 用 alphaTab 的 MIDI 导出 API。

## 数据模型与文件布局

**SQLite 两张表**：`scores`（id, title, composer, instrument: piano|guitar|other, source_type: pdf|png|jpg|musicxml|gp, status: imported|processing|ready|failed, original_path, musicxml_path, cover_path, page_count, error_message, created_at, updated_at）、`jobs`（id, score_id, kind, state, progress, message, 时间戳）。

**app-data 目录**：`library.db` + `scores/<id>/original.*、score.mxl、page-1.png…` + `covers/<id>.png`。

## 里程碑

**M0 — 脚手架 + 技术验证（最高优先，消除两大风险）**
- create-tauri-app 初始化（Tauri2 + React-TS + Vite）+ Tailwind。
- Spike A：本机安装 Audiveris 5.4（GitHub release，需 Java 17+），用 samples 里的扫描 PNG/PDF 跑通 CLI batch → 确认输出 .mxl 与日志格式，记录准确参数。
- Spike B：裸页面接 alphaTab：加载一个 MusicXML 渲染+播放；验证压缩 .mxl 导入（有问题则 Rust 解包传 .xml）；确认 soundfont 离线加载方式。
- 任一 spike 失败 → 计划回退方案（见风险）后再继续。

**M1 — 曲库核心**
- db.rs 迁移；Rust commands：import_files / list_scores / get_score / update_score / delete_score / read_score_asset。
- 导入：拖拽 + 文件对话框，按类型分流（mxl/gp → ready；pdf/png → 待识别）。
- 曲库 UI：网格/列表视图、搜索、按乐器/状态筛选、封面缩略图、状态角标。

**M2 — 查看 + 播放**
- ScoreDetail：alphaTab 谱面渲染（缩放、横向/分页滚动）。
- 播放条：播放/暂停、进度、循环选段、变速(0.5–2x)、音量、轨道选择/静音。
- PDF/PNG 导入的条目：查看原图页对照（识别前的原始谱面）。

**M3 — OMR 识别管线**
- audiveris.rs：串行任务队列（JVM 重，避免并发）、Tauri event 推进度（解析 stdout 步骤日志）、取消、错误捕获（日志尾部展示到 UI）。
- 多页 PDF 整本识别；完成后刷新元数据与封面；支持重新识别。
- Settings 页：Audiveris 路径覆盖（开发期用本机安装，发布用打包资源）、DPI/参数。

**M4 — 打包打磨**
- 打包 Audiveris（jlink 定制 JRE + jar + tesseract dylib + tessdata）与 pdfium/soundfont 进 resources，实现完全离线；出 macOS dmg。
- 导出 MIDI / 导出 MusicXML；深色模式；关于页含 Audiveris/alphaTab 开源署名。

## 验证

1. `samples/` 样例集端到端：钢琴印刷体 PDF → 识别 → 查看 → 播放；拍照质量 PNG 识别；.gp5 六线谱导入播放；.mxl 直接导入。
2. Rust 单测：db 迁移/CRUD、mxl 元数据解析、audiveris stdout 解析（mock）。
3. M0 两个 spike 的验收记录作为继续开发的门禁。
4. 最终以 `tauri dev` / `tauri build` 出的 dmg 走一遍完整流程，断网验证 soundfont/识别均离线可用。

## 风险与对策

- **Audiveris CLI/macOS 环境坑**（tessdata、dylib 加载）→ M0 先行验证；发布包用官方 release 自带 natives + jlink JRE。
- **alphaTab 对 Audiveris 产出的 MusicXML 兼容性** → Rust 侧解包 .mxl、必要时清洗 XML；最坏情况引入 OSMD 做钢琴谱渲染兜底（播放仍用 alphaTab）。
- **识别准确率**（低质量扫描/拍照下降明显）→ 预期管理：UI 明示"识别≠完美"，支持对照原图 + 重新识别；手写谱不在范围内。
- **JVM 启动慢（每次任务数秒）** → batch 模式一次跑多个任务；队列串行。
- **安装包体积 ~200MB**（JRE+jar+tessdata）→ 个人/开源可接受；已在选型时确认。

## 非目标（MVP）

谱面编辑/修改、六线谱扫描识别、手写谱识别、云端同步、Windows/Linux 打包。
